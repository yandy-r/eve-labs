# eve-labs — Agent Rules

EVE-NG Pro lab topology files (.unl XML) for the EVE host `eve`, versioned in git.

This is the canonical, tool-neutral repository policy.

## Commands

```bash
pnpm install                 # dev tooling (prettier, markdownlint, biome, commitlint)
bash scripts/install-lefthook.sh  # git hooks
```

```bash
make test                    # check-labs (XML + unique <lab id>) + localize-test + localize-check
```

```bash
make lint                    # ./scripts/style.sh lint; `make format` to auto-format
```

## Project conventions

- Lab files are EVE-NG Pro 7.2 `.unl` XML, edited in the EVE web UI on host `eve`
  (`/opt/unetlab/labs`); do not hand-reformat them — EVE rewrites them on save.
- Every `.unl` needs a unique `id` attribute on `<lab>` (EVE 7 rejects labs without one).
- Lab files must be owned by `www-data` on the host so EVE can save them.
- Cloud networks: `pnet0` = management (10.100.51.0/24, trunk); `pnet2` = VM traffic trunk (VLANs
  1240-1243); `pnet1`, `pnet3`-`pnet9` are not brought up.
- Layout: `labs/ccie/`, `labs/datacenter/`, and `labs/cloud/` personal labs; `Shared/` and `Users/`
  are EVE default folders.
- Thumbnails (`*.unl.jpeg.*`, `*.unl.png.*`) are binary and generated by EVE.
- Python tooling lives in `python/` (src layout, package `evelab`: `evelab.common` = shared building blocks,
  `evelab.localize` = eve-localize; stdlib-only Python 3.11, no install needed; config in
  `python/pyproject.toml`; tests: `make localize-test`). New tools get their own subpackage and a shim in `scripts/`.
- Site localization: `scripts/eve-localize` (package `python/src/evelab/localize/`,
  tests in `python/tests/localize/`, guide `localize/README.md`, design
  `docs/internal/lab-localize-design.md`). Committed labs stay at baseline; each lab with cloud
  networks has a `<stem>.localize.toml` manifest next to it. After changing such a lab, run
  `./scripts/eve-localize discover <lab> --update`, review the diff, and keep `make localize-check`
  green (`profile --example` regenerates `localize/site.example.toml`).

## MUST / MUST NOT

- **Never** commit secrets: `.env`, tokens, API keys, credentials.
- **Commits**: Conventional Commits 1.0.0 — `feat|fix|docs|refactor|perf|test|build|ci|chore(scope):
description`. Use `docs(internal): …` for internal plans or research docs.
- **Issues**: use `.github/ISSUE_TEMPLATE/` forms when present; never open title-only issues.
- **Pull requests**: follow `.github/pull_request_template.md` when present; link the issue (`Closes #…`).
- Follow [CONTRIBUTING.md](CONTRIBUTING.md) and the label taxonomy in
  [`.github/labels.md`](.github/labels.md) when present.
- **Modularity**: small, cohesive units with minimal coupling; extract shared logic instead of copy-pasting.

## Branching & releases

[`RELEASING.md`](RELEASING.md) is the source of truth for branches and releases. Branch
off `main` and PR back into it; every release is tagged from `main`. Never merge one
long-lived branch into another to sync it.
